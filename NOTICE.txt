Name: Equalizer APO
Version: 1.4.2 (source commit bbfcc3e5024cbb9d61ba75fc88d78605cc4c9687)
Licence: GPL-2.0-or-later
Copyright: Copyright (C) 2012-2025 Jonas Thedering and contributors
Website: https://sourceforge.net/projects/equalizerapo/
Used for: The master effects run in Equalizer APO (OmniControl adds its chain through its config language). OmniControl ships Equalizer APO's audio-processing part unmodified: EqualizerAPO.dll with the libraries it loads (fftw3f.dll, sndfile.dll, msvcp140.dll, vcruntime140.dll, vcruntime140_1.dll), taken without installing from the official installer EqualizerAPO-x64-1.4.2.exe (SHA-256 7403BE7427BBE1936A40DDED082829B6E217FC4F5990FEE5CBA501F0AE055AFA, MD5 as published on SourceForge) and kept with its licence text (LICENSE-GPL-2.0.txt) in the equalizer-apo folder next to OmniControl; its exact source code is the official EqualizerAPO-src-1.4.2.zip at the website above. Setup's "Equalizer APO" task or the first use of a master effect copies these files into Program Files\OmniControl\EqualizerAPO and registers them; a separately installed Equalizer APO is never changed. OmniControl's own device code is a C# port of Equalizer APO's Device Selector logic (DeviceAPOInfo.cpp: the device checks, the default install mode, keeping and restoring the original effects under Child APOs, the install modes and troubleshooting options; DeviceTestThread.cpp and ReceiveThread.cpp: the check that the APO started; helpers/ServiceHelper.cpp: restarting Windows audio; helpers/RegistryHelper.cpp: taking a device key over when it refuses a new key; Setup/Setup.nsi: what an install writes; Core/Engine/Apo/DeviceApo, AudioService, ApoDeviceTest, ApoSetup), used under GPL-3.0-or-later through the licence's "or any later version" option.

Name: Windows Packet Filter (WinpkFilter, ndisapi)
Version: 3.6.2
Licence: MIT
Copyright: Copyright (c) 2018 Vadim Smirnov
Website: https://github.com/wiresock/ndisapi
Used for: Download limits per program: while a limited program has network connections, received packets are tunnelled through its NDIS filter driver (ndisrd.sys) and limited programs' packets are paced. Shipped unmodified: the Windows 10+ x64 driver files (ndisrd.sys, ndisrd_lwf.inf, ndisrd.cat, signed by Microsoft's hardware programme) taken from the official installer of the v3.6.2 GitHub release (Windows.Packet.Filter.3.6.2.1.x64.msi), with its licence text, are in the windows-packet-filter folder next to OmniControl; Setup installs them with Windows' netcfg when its "Install Windows Packet Filter" task is chosen, OmniControl does the same after checking their SHA-256 when the person asks, and uninstalling OmniControl removes the driver only if OmniControl installed it. OmniControl talks to the driver with its own declarations of the device's control codes and structure layouts, taken from ndisapi's include/Common.h (MIT; licence text at https://github.com/wiresock/ndisapi/blob/master/LICENSE).
