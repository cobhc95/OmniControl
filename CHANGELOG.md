# Changelog

Versions go 0.1.0, 0.1.1 ... 0.1.9, then 0.2.0. Each release is a GitHub pre-release with a Setup and a Portable download.
New entries go under "Unreleased" as work lands; a release moves them under its version.

## Unreleased

- Fixed: tooltips inside pop-down menus (Method, Plays on, presets and others) showed almost at once; every tooltip in the app, menus included, now waits 1 second of resting the pointer.
- New: Resources > Taskbar gadget > What it shows: every temperature row (CPU temperature, GPU temperature, Hottest sensor and each disk's temperature) has a chip under its name with the sensor it reads ("Auto · Core (Tctl/Tdie)", or the chosen sensor and its value); it opens the same sensor menu as the Readings tab. Each temperature reading has one sensor choice, used alike by the Readings tab, the gadget, its tooltips, its state and rules; a disk's temperature can now be read from any sensor too. Choices made before are kept.
- New: the taskbar gadget can sit on the left of the taskbar: "Position" (Right / Left) beside "Show on taskbar", and "Position" in the gadget's right-click menu. Left puts it after the Widgets button (or at the taskbar's left edge), or, with the taskbar icons left-aligned, after the last app button; it follows app buttons as they come and go within a few seconds. One position for every layout.
## 0.2.7 (21 Nov 2026)

- Important: Other PCs uses a new connection protocol in this version (safer pairing and fresh keys for every connection). Update every PC you pair to 0.2.7 or later; until both PCs run it, existing pairs show offline and new pairing is refused with one sentence. (This comes from the protocol change, not from the move to .NET 10, which needs nothing from you: the app still brings its own .NET.)

- Fixed (GitHub issue #2): OmniControl no longer takes over your sound. With no effects it routes nothing: it never makes a virtual cable Windows' default device and never sends programs through one, so a mixer of your own on VB-CABLE (or Voicemeeter) keeps working without an echo. On upgrade, a setup with no effects anywhere is put back as Windows had it (default device and every program's device).
- New: every row's Method menu starts with "Off — no effects", the default for the master, programs and microphones (also for rows with no effects after the upgrade; rows with effects keep Automatic). Off routes and processes nothing; the line under the Method chip says "pick a method to use effects", the FX button is greyed and opens the Method menu, and adding an effect while Off opens it too. Easy view's sound steps pick Automatic for the row they set up.
- Changed: virtual cables are used only once you switch them on under Volume > Wiring > Virtual cables (a cable already on the PC may be another program's); a cable you mark yourself is switched on. Existing setups with effects keep the cables they used. A cable that is Windows' default or that a program plays on is never taken for effects.
- Changed: Plays on lists every output device, virtual cables included ("Cable"; one OmniControl uses is shown dimmed with what uses it, "Master bus" for the bus's).
- Changed: Restore defaults (Volume) also sets every method to Off and switches every virtual cable off, so all routing stops and Windows' default device and programs' devices go back.
- Fixed: "GPU temperature" could show the graphics card's memory junction (or hot spot) instead of the GPU itself; it now prefers the core (edge on AMD), then hot spot, memory and regulator sensors last. "CPU temperature" now prefers the CPU package (AMD: Tctl/Tdie) over single cores and CCDs, and the ACPI thermal zone only when the CPU's own sensor cannot be read (no PawnIO driver); Hottest sensor on Auto is still the hottest of all. The CPU and GPU cards on the Resources page show their temperature as a chip whose menu picks the sensor ("Auto" or any temperature sensor), as the Hottest sensor card does; the choice is kept per reading and falls back to Auto, saying so in the menu, when that sensor is gone.
- Lighter memory: every control carries less styling (fixed sizes and icons no longer follow the theme they never change with; the tray panel's, the screenshot overlay's, the browser tabs' and the FX window's own styles are matched only in their own windows), about 15 to 20 MB less with the main window open; nothing looks different. A slider being adjusted from the keyboard, a level meter and a choice chip no longer keep a let-go main window in memory, and timing-log.txt says after each let-go whether the window really left memory.
- Fixed: the taskbar gadget was invisible on Windows 11 since windows are drawn in software (Windows 11's taskbar covered it); it is drawn as its own see-through window in the taskbar again, looking as before.
- Changed: when the sign-in task is removed because something in OmniControl's folder can be changed without administrator rights, the errors log names that file or folder.
- Lighter memory: windows are drawn in software, so the graphics driver and ANGLE are no longer loaded (about 50 to 100 MB less, and no graphics-card memory); the download is about 2 MB smaller.
- Lighter memory: after OmniControl has sat in the tray for 5 minutes, its main window and the Actions and hotkeys window are let go and their memory given back by a background collection that never pauses the mouse or the sound (and none at all while sound plays through OmniControl's effects or a screen recording runs); the next opening takes a moment longer and comes back at the same place, page and scroll. The quick panel stays ready from start-up and is never let go, so it always opens at once.
- Lighter sensors: temperatures (CPU, graphics card, board, Hottest sensor) are read every 5 seconds, also while the gadget shows other readings every second; with a chosen Hottest sensor only its own hardware group is kept open (the board's only when the sensor is on it).
- Lighter sensors (2): GPU usage, disk activity and the graphics card's and drives' temperatures now come from Windows itself, as Task Manager shows them; LibreHardwareMonitor is loaded only for the CPU temperature, a reading Windows does not give (a drive or card that reports no temperature), a sensor of its own chosen for a reading, or while the sensor menu is open. Readings can differ a little from before (GPU usage is the busiest engine).
- Privacy: devices-log.txt no longer keeps MAC addresses, the Wi-Fi name, device ids or the place a smart plug reports, and each line is cut to 600 characters instead of kasa's whole answer.
- Lighter start-up and memory: the Mouse and Trackpad, Smart Devices, Other PCs, Automation, OSD, Resources and App settings pages are made the first time they are opened or searched instead of at start-up (their actions, presets and OSD pop-ups work from the start as before); the first opening of each, or the first search, takes a moment longer.
- Diagnostics: timing-log.txt records the app's memory (managed heap, private bytes, working set) two minutes after start, each time the window has settled hidden and after the windows are let go.
- Security: Setup and uninstall no longer start cmd while elevated (it would run your AutoRun command as administrator): they ask OmniControl to quit through its own quit signal instead of running OmniControl.exe, look for it and the network service with Windows' own tools by full path, and run netcfg directly; the old per-user copy's uninstaller (0.2.3 and earlier) runs with your normal rights, never as administrator. "Restart Tailscale" restarts the service through PowerShell instead of cmd.
- Security: a mouse button or middle-click gesture that starts a program, opens a path, or searches a custom address that is not a web page runs only once it is allowed on this PC: choosing it on the Mouse page allows it, one that came by an import or a restore asks "Allow this button or gesture?" at its first press. Your mappings from before this version stay allowed. Importing mouse settings no longer brings "Run as administrator" (starting OmniControl elevated).
- Security: plug-ins load their own DLLs only from their own folder and Windows' System32 (a plug-in that needs a DLL found through PATH no longer loads) and never from a mapped network drive; restoring a backup leaves out effects' plug-in and impulse-response files and their saved state, as an import from another PC does: choose them again after a restore.
- Security: OmniControl talks to the network service only after checking that the program answering on its connection is the service itself, and says so in one line otherwise; the network service and the sign-in task are set up only when every file in OmniControl's folder (not only the folder) can be changed by administrators alone.
- Security: Equalizer APO's config files are checked and written through the same open file, so a file swapped for a link in between is never followed.
- Security: memory limits on outside data: a backup is refused when all it holds unpacks to more than 64 MB or it holds a settings file twice; an Android screenshot larger than 16 million pixels is not read, and only the rows its header promises are unpacked; a hidden command's output is kept only up to what the log needs while it prints.
- Security: a screen recording whose action asks where to save is recorded into a private folder of yours (%LOCALAPPDATA%\OmniControl\Recording) and moved to the chosen place only on Save; Discard deletes it, and a recording left there by a run that ended first is deleted at the next start.
- New: each release has a SHA256SUMS file beside the Setup and Portable downloads, to check a download is the published one.
- Changed: OmniControl now runs on .NET 10 (long-term support, still carried inside the app; nothing to install). The Setup is about 0.2 MB larger.
- Security: Other PCs speaks protocol 3: update every PC to this version, or they no longer see or reach each other (already paired PCs stay paired and reconnect once both are updated). Pairing: the PC that is asked makes a new code for each attempt and the code is checked without ever being sent (CPace), so "Pair with <name>?" now means the code shown there really was typed on that PC; a wrong code or a PC that is not pairing no longer closes pairing (five wrong codes do); closing the panel stops a running pairing at once. Every connection gets fresh keys, so a pairing key that leaks later does not open recorded traffic. A newly paired PC may run this PC's power actions only once you allow it (its menu, Allowed here). A paired PC can relay a wake only for another PC this PC is paired with, and only when it may run power actions here. A flood of messages from a paired PC is held back instead of queuing up; an answer from one PC can no longer be taken for another's.
- Volume: a "Use microphones" switch on the Microphones group (off by default; on after the update if a microphone already had effects or a combined microphone exists). Off, OmniControl opens no microphone: no level meter capture, no microphone effects or combined microphones, no Listen, so Windows' microphone-in-use icon does not appear because of OmniControl; level and mute still work. Restore defaults turns it off; it is searchable and has a toggle action.

## 0.2.6 (21 Nov 2026)

- Security: pairing a PC now asks "Pair with <name>?" on the PC that shows the code too, a PC that is already paired must be unpaired before it can pair again, and the PC names are part of what both PCs prove (a name with hidden direction marks is cleaned). Both PCs need this version to pair.
- Security: while OmniControl runs as administrator, everything it starts (programs, files, web pages, commands, scripts, custom actions, Python and pip, adb, Tailscale) runs with your normal rights; only a step's own "Run as administrator" elevates. Windows' own tools are started from the Windows folder by their full path.
- Security: custom actions that start something and scripts ask "Allow …?" once the first time you run them (again after they are changed); a rule or another PC can run them only once allowed.
- Security: the sign-in task (Run as administrator without a prompt) is kept only for the installed version in Program Files; a task left by a portable or per-user copy is removed, and a copy started by the task acts only on its restart and background-start arguments.
- Lighter when idle: Smart Devices no longer looks for emulators, asks adb or reads the emulators' memory unless a device uses simulation or the Devices page is open, probes Python at start only when a device uses Scripts, and runs its auto-check timer only for a repeating auto-check; the autoscroll block sleeps while the mouse rests; the OSD keeps no windows or media watcher while it is off; spinners stop animating while hidden; network speeds take one look at Windows' adapter table per read; giving memory back no longer pauses the mouse and sound; settings are written off the UI thread.
- Lighter when idle (2): the Equalizer APO folder check runs only with folders to check (every minute while they are watched); the Volume page and FX window no longer hold fine timers for their meters, and meters draw without new objects per frame; the UI watchdog and the clock check wake every 5 and 10 seconds; the power journal decides a wake once instead of ticking; the laptop brightness check stops on a PC without a laptop panel; the drives' sensors are read every 30 seconds when only their temperatures are wanted; warm light ticks only while it is on; the touchpad settings watch is not asked again on top of itself; automations look every minute while no rule is on; "Pause in full-screen apps" follows Windows' window notices instead of asking twice a second; the taskbar gadget and the Resources readings do less per read; Skia's GPU cache is capped at 16 MB.
- Changed: the names on the gesture areas overlay follow the app's light or dark theme (window areas) and the ink drawn on the accent (edge strips); the mixer looks for programs every minute while no volume view is open (new sessions still show at once) and reads each program's path once.
- Fix: a damaged settings file is kept as name.bad.json before its defaults are saved over it, and the status line says which files were reset (once).
- Fix: a failure inside a button's or menu's handler, or in work started in the background, is written to errors-log.txt instead of being lost or showing the "Something went wrong" window.
- New: each paired PC's ⋯ menu has "Allowed here": whether it may run this PC's power actions (always behind this PC's own countdown, and never counted as a person's press), its other actions and settings, and read this PC's settings and device set-ups. Reading is off until you allow it, and every read is said in the status line.
- Security: Other PCs speaks protocol 2 (a connection's kind is part of its proof): update every PC to this version, or they no longer see or reach each other. Listening and announcing stop while no PC is paired and pairing is closed; beacons and connection attempts from one address are limited.
- Security: plug-ins load only from this PC's own drives (never a network share), and while OmniControl runs as administrator only from folders only administrators can change. An import from another PC leaves out effects' plug-in and impulse-response files and their saved state; importing or restoring app settings no longer brings plug-in folders or the update state.
- Security: a script runs from a temporary file that is held so nothing can change it before it runs; OmniControl refuses to write Equalizer APO's config folder when a file there is a link; the Tailscale firewall rule is for OmniControl's own program only; Setup runs only the old per-user copy's own uninstaller and starts the app's steps without cmd.
- Security: only https and Settings pages open as web pages (a router's page and a picked screenshot link may be http), and the update link opens only on GitHub.

## 0.2.5 (21 Nov 2026)

- Changed: tool tips no longer repeat the words already on screen (menu rows, chips, names, notes); a trimmed text shows its full words as a tip only while it is really cut off.
- Changed: on Resources, "Network by app" is now "Network traffic control", and the Packet filter switch sits on its header line (Restore defaults of the group turns it back on).
- Fix: a click on the taskbar gadget runs sooner: it waits Windows' double-click time counted from the press rather than from the release, so a double-click (Task Manager) is still recognised; with no double-click action every click runs on the press.
- New: favourite actions. Star an action in any Choose-an-action window (on its row, or beside its name in the settings pane); starred actions get a Favourites section at the top of the sidebar and show first in their own section, in every place that picks an action.
- Fix: the hover in pop-down menus no longer drops out while the mouse rests on a row: menus with live values (the Resources temperature sensor and network adapter menus, Plays on, Add program) update their rows in place instead of redrawing them every second. The preset, Sound, Apps scope ("Works in"), Plays on, Add program, rule link ("and" / "then wait"), app list manager and preset manager "…" menus now use the one shared menu, so they look and behave the same everywhere: the accent bar marks the current choice (the rule link's "now" tag is gone), a value sits at the row's right, "Manage …" rows are muted, and a device that can't be used is greyed with its reason as tooltip.
- New: the Tailscale checklist checks that Windows still gives Tailscale's adapter its address on this PC, with a "Restart Tailscale" fix; when only "Reaches OmniControl on it" fails, it suggests restarting Tailscale on that PC.

- New: "Send keys" (first in Editing and keys; it was "Send a shortcut") remaps a mouse button, trackpad gesture, middle-click or gesture rule step to any key or combination you type (F13, Enter, A, Ctrl+Shift+Esc, Win+Shift+S) or a short sequence of up to 8 separated by commas or spaces ("Ctrl+K, Ctrl+C"), sent in order; the card shows the keys themselves. An unknown key name shows one sentence under the box (also for "Also send this shortcut", which now takes sequences too). "Keys held down while the button is held" holds a single combination; a sequence is typed once on the press. For a keyboard hotkey or an automation rule, make a custom action of the new type "Send keys". Keys sent in a runaway (over 100 shortcuts a second) are stopped, and a shortcut Windows takes only half of is released at once.
- New: while Remote Desktop, a virtual machine or another remote-control app is in front, a mouse button's or trackpad gesture's volume, mute, play or pause, next or previous track and Close window action is sent to it as the standard key, so the remote PC acts instead of this one (Mouse page, "Send actions to remote PCs as keys", on by default; the mouse log names each one). Fix: shortcuts from a button or gesture (Switch window's Alt+Tab...) reach a Remote Desktop whose "Apply Windows key combinations" is "On the remote computer": they are typed into a remote window key by key, like a keyboard, instead of all at once. Where Remote Desktop keeps them on this PC ("On this computer", or not full screen with the default setting), Alt+Tab, Alt+Shift+Tab, Alt+Esc, the Windows key, Ctrl+Esc and Ctrl+Alt+Del go as its own replacements (Alt+PageUp, Alt+PageDown, Alt+Insert, Alt+Home, Ctrl+Alt+End). Media and volume keys always carry their standard scan code.
- Fix: Setup adds the Windows Firewall rule that lets your other PCs reach OmniControl over Tailscale (and the uninstaller removes it), so no PC is left "not reachable" on Tailscale after installing.
- Fix: the Other PCs page no longer shows a narrow jumble of the Volume page's Easy view in place of its PC tabs; a PC with no power countdown shows no tag again.
- New: the taskbar gadget's readings list has two rows for each physical disk, its activity and its temperature (named "Disk 0 activity (model)" and "Disk 0 temperature (model)"); a disk added or removed joins or leaves the list by itself and keeps its settings, and a drive that reports no temperature shows "—".
- Faster: going back to a page of the main window is instant (each page is built the first time it opens and kept, also while the window is hidden, so opening it from the tray is instant too), and the Actions and hotkeys window opens again at once (it is hidden, not closed, and still starts fresh each time); the app's screens bind to their data without run-time lookups (compiled bindings), so windows and pages build a little faster; the app and its UI core come precompiled, so it starts and opens things with less waiting (the Setup is about 5 MB larger), and every page builds faster the first time (a card builds only the layout it shows, not its full, half-width and knob layouts all at once).
- Fix: the taskbar gadget comes back after Windows Explorer restarts (Task Manager's Restart or a crash), and appears once the taskbar is there when OmniControl starts before it. Its text colour and the tray icon follow a change of Windows' light or dark mode even when the app mode stays the same, and on a Windows 10 taskbar at the left or right edge the gadget sits above the tray instead of in the middle of the bar.
- Fix: while a download limit is active, Windows Packet Filter no longer takes over Tailscale's (WinTun) adapter, so other PCs over Tailscale stay reachable. Download limits do not apply to traffic arriving through a WinTun VPN (Tailscale, WireGuard).

- New: Resources has a "Packet filter" switch. Off takes Windows Packet Filter's driver out of every network adapter (Windows asks unless OmniControl runs as administrator), for a conflict with other software; download limits are then kept but not applied, while upload limits and blocks keep working. On, or Restore defaults, puts it back.

## 0.2.4 (20 Nov 2026)

- Fix: on Other PCs, a PC reached over Tailscale or another address that said it went to sleep, hibernated or shut down is no longer called, checked or pinged until you press Wake, press Check now, or it shows up again (it connects to this PC or is seen on the network), so that traffic can't wake it. Its tag says "Asleep" or "Shut down" meanwhile, also after a restart of OmniControl.

- Security: Other PCs sends a wake signal only when you press Wake (or Test wake) for that PC, or its "Wake <PC>" key, button or tile: one signal per press, never sent again by itself, never from a rule, a chain or another PC's request, and nothing is kept across a restart. A PC asked to pass the signal on does so only for a press made on the PC that asks (an older OmniControl's request is refused). If the signal can't be sent, the status line says so once; press Wake again.

- New: the FX window has an Edit menu with Undo and Redo (Ctrl+Z, Ctrl+Y or Ctrl+Shift+Z), named after the step ("Undo Remove Compressor", "Undo Change Gain"). Adding, removing, moving, pasting and switching effects, the Effects on switch, presets, loading a chain and every setting are undone; a whole knob or slider drag is one step. The history is cleared when the window closes.

- New: on Other PCs, a PC's Sleep, Restart, Shut down and Sign out pills show the countdown that PC will use ("in 30 s", its own setting). Once it accepts, the pill reads "Sleeping in 0:25" with the accent fill growing, a Cancel pill beside it cancels there, and a "Sleep in 0:25" tag shows on its tab and header, then "Going to sleep…" and "Asleep" or "Off". A PC on an older OmniControl shows the pills as before. "Cancel power countdown" is a new action (never blocked).
- New: each microphone on the Mixer tab has the same Method menu as the master: Automatic, Cable bus (needs VB-CABLE) or Equalizer APO on that microphone (no cable, no delay; its chain is written into Equalizer APO's config for that device only), with the same box colours, line under it and "Equalizer APO devices…" step. A combined microphone's menu shows Cable bus and says why Equalizer APO can't run it. Restore audio defaults puts microphones back to Automatic.
- Changed: the line under the master's or a microphone's Method box says "no delay" while Equalizer APO is on that device and working (it said "on the speakers").
- New: OmniControl ships Equalizer APO's official 1.4.2 installer, unchanged, and uses Equalizer APO as its own program (its own installer, Device Selector, uninstaller and Installed apps entry). Setup's task "Equalizer APO" (on by default, skipped when it is already installed) runs it silently; its Device Selector opens so you tick your speakers, and the finish page says to restart Windows if its check showed a device that didn't start. When it isn't installed, "Install Equalizer APO…" (also in the Portable version) runs the same installer with one administrator prompt, and the first use of a master effect offers it once instead of installing anything by itself. "Equalizer APO devices…" opens its Device Selector. Uninstalling OmniControl leaves Equalizer APO installed.
- Changed: the master's Method chip is green "Equalizer APO" only while it is on the master's speakers and Windows loads it there; red "Equalizer APO · not running" with "sound plays without effects" when it is on them but Windows doesn't load it (audio enhancements off, not registered); plain with "not on this speaker yet" when it isn't on them. The Method menu's Automatic card says the same, and the Equalizer APO card says "On <speakers>" or "Not on <speakers>", with "installed separately" beside its name.
- Changed: the accent's default shade is stronger, close to Windows' raw accent colour (as toggles look on the taskbar); the Accent intensity slider still goes paler (down to 0) or stronger, and 50 is still Windows' own shade. A saved 50 (the old default) counts as the new default at start-up.
- Changed: every colour comes from one place; the OSD's Grey accent is one of the accent choices and shaded at Windows' strength like the rest.

- Fix: the OSD's bar, ring and icon use the same accent shade as the rest of the app (Windows' own, following the accent, intensity and the pop-up's dark or light background) instead of the raw, deeper accent colour.

- New: the Volume page's Wiring tab has an Equalizer APO group: whether it is installed, and its one step ("Equalizer APO devices…" or "Install Equalizer APO…").
- New: the accent colours are Windows' own accent palette, so they look as rich as "Windows accent"; a "Custom…" dot opens a colour editor (saturation square, hue bar, hex box, Hue, Saturation and Brightness sliders, live preview), and one Accent intensity setting makes every accent softer or stronger than Windows' own shade.
- Changed: every colour choice (Theme, Accent colour, Background colour, Tray icon colour, the OSD's Accent and Background, the gadget's Text, warn and icon colours) is now a compact swatch button showing the chosen colour and its name; it opens a grid of all the colours (arrow keys move, Enter picks), Left/Right and the mouse wheel still step the choice, and the accent's "Custom colour…" row opens the colour editor. The custom colour's dot has a rainbow ring so it never looks like a preset.
- Fixed: a remote playback device (Remote Audio) is no longer taken for a microphone when OmniControl reads where Equalizer APO is: such a device has no effect slots in Windows, and the master's Method menu says Equalizer APO can't run there.
- New: the Hottest sensor card has a sensor menu (Hottest (auto), or any temperature sensor grouped by hardware with its value now); the card, its state and the gadget then follow that sensor, and the card draws a 25-100 C graph along its foot that turns warm past 70 C.
- New: per-app network limits, blocks and speeds work without running OmniControl as administrator, through the small OmniControl Network service (Setup's task "Network service", on by default, or "Install…" on Network by app; one Windows prompt). Windows starts it when a limit or the speeds need it and it stops itself when idle; every rule leaves Windows when OmniControl closes. The status line says whether it runs; App settings › Your data › Network service › "Remove…" takes it away, and uninstall removes it.
- Changed: "Run as administrator" is needed only over administrator windows; without the service, OmniControl as administrator still does the network work itself.
- Changed: Setup installs OmniControl for all users into Program Files (one administrator prompt for the whole install, no more prompts for its steps); settings stay per user in %APPDATA%\OmniControl. An older per-user install is closed, uninstalled silently (settings and Windows Packet Filter kept) and its folder removed; the shortcuts, "Start with Windows", the sign-in task and the network service follow the new folder.
- Security: the network service, which runs OmniControl.exe as SYSTEM, is installed only from a folder that only administrators can change (checked from the folder's access rights), so nothing running as the user can swap the program it starts. The Portable version offers no service and says "Network service needs the installed version"; as administrator it still does the network work itself.
- Fixed: shortcuts sent by mouse buttons, gestures and rules carry the key's real scan code, so they reach Remote Desktop, virtual machine consoles and games that read scan codes.
