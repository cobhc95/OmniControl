# Changelog

Versions go 0.1.0, 0.1.1 ... 0.1.9, then 0.2.0. Each release is a full GitHub release with a Setup, a Portable download and checksums.
New entries go under "Unreleased" as work lands; a release moves them under its version.

## Unreleased

## 0.3.3 (23 Nov 2026)

### ✨ New

- **Tray panel timings** in App settings > Appearance: **Panel reopen delay** (ms), **Tile refresh spacing** (ms) and **Tile refresh at most every** (s). The defaults are the old fixed values (400 ms, 400 ms, 10 s), and double-clicking a slider restores them.

### 🛠 Fixed

- "Open Task Manager" said Windows refused to start it with normal rights when Task Manager was found through the Start menu or App Paths instead of Windows' folder; it now always opens through the shell's administrator prompt.
- The tray panel could hide itself when a tile's menu closed or an action picker opened (Tile, Slider, Change action, Change icon), so the action could not be chosen; it now stays open while a picker is up.

### ✏️ Renamed and tidied

- The built-in tray panel no longer starts with a "rotate to portrait" tile (add it from the panel's Edit if you want it).

## 0.3.2 (22 Nov 2026)

### ✨ New

- **Search finds everything.** Every page, choice, menu item, tooltip and the Presets Manager are searchable. Exact matches come first; a misspelling shows "No exact matches" with "Similar matches" (typo-tolerant), and the matching text is highlighted. A test keeps new pages from being missed.
- **Presets Manager** has its own sidebar entry (above Actions and Hotkeys). Each preset row has its hotkey box, "Switch to", rename and delete icons, and a link: "* <triggers> · Edit in Automation" or "More options in Automation", which starts a ready rule that switches to that preset.
- **Every preset is an action**, with or without a hotkey: use it in rules, mouse buttons, gestures and tray tiles. Actions and Hotkeys has a **Presets** section, each preset group gets **Next · Previous**, and "Switch to" has **Run again to switch back** (off by default).
- **Automation:**
  - **Custom Rules** (renamed from Rules) holds your rules, including preset rules.
  - **From other pages** lists what pages run by themselves as real, editable rules: warm light, per-network traffic limits, smart device checks and the emulator's idle close. Your existing settings move into them once.
  - Pause all rules and switching automation off stop only your own and preset rules; those page rules keep running.
- **Choose a trigger or state** is one list with icons, grouped under "PC and time" and "Your pages", with live values. **Programs are states** ("Steam is running": starts, closes, or starts or closes), with "＋ Add a program…" to browse for an .exe and a tag saying where each program came from. Your existing program rules are converted and behave the same.
- **Network states:** "Connected to <network>", "On a metered connection" and "Not connected" for rules and presets.
- **Network Traffic Control:**
  - an **Adapter** pull-down, with saved networks under each adapter, gives an adapter or a network its own limits and blocks (the most specific wins);
  - an **All apps** row sets every app at once;
  - its own presets;
  - its own settings file, apart from Resources.
- **Mouse:** actions can run when a button is **pressed twice or three times** ("Presses within", 300 ms by default); their pills say "· twice" / "· 3 times".
- **Backup and restore:** Export, Import from a file and Import from another PC share one window. You tick the areas, named like their pages, and every saved area is included.
- **Other PCs:** a **"Can't reach it on this network?" checklist** appears when a PC can't be reached or none shows for pairing. It checks Private/Public (with "Make it Private"), Windows Firewall (with "Allow on Private networks"), ports in use, other versions and pairing keys.
- **Screenshot:**
  - "Read QR code" also reads Aztec, Data Matrix, PDF417 and common barcodes, including light-on-dark and small codes.
  - Copying a screenshot shows "Screenshot copied".

### 🛠 Fixed

- **Other PCs** couldn't be found on the local network when the PC had an adapter with IPv4 off (for example Hyper-V's Default Switch), and switching a network to Private wasn't noticed until a restart. Setup now allows OmniControl on Private and Domain networks, never Public.
- **"Open Task Manager"** (gadget double-click, hotkeys) opens again when OmniControl runs as administrator, and the gadget no longer says its click action is unavailable right after start-up.
- **Pop-down menus** whose choices sometimes did nothing, and preset rows that lost their buttons.
- **Lists in the trigger picker** no longer flicker or scroll away by themselves.
- **The screenshot editor's empty text box** goes away when you change tool or click elsewhere.
- **Setup's "Choose features" page** no longer ignores the first click on Next.
- **Links to another page** bring the main window to the front.
- **The search box** shows "Search settings…" again.

### ⚡ Lighter and faster

- **Pages show their first cards at once** and build the rest between frames. Pointer settings, "Start with Windows" and microphone levels are read off the UI thread.
- **"Free memory after closing"** also hands the freed memory back to Windows, and .NET keeps a smaller memory budget.

### ✏️ Renamed and tidied

- **New names:** Audio and Volume, Presets Manager, Actions and Hotkeys, Network Traffic Control, and "Choose an action".
- **Custom actions** are made and edited only in Actions and Hotkeys, and deleting one asks first.
- **The taskbar gadget's right-click menu** is just Gadget settings…, Network Traffic Control… and Hide gadget. On the gadget tab, Position and Font sit at the right.
## 0.3.1 (22 Nov 2026)

- Windows' own volume pop-up is hidden from the first key press after OmniControl starts.
- Fixed: Setup's Choose features page no longer ignores the first click on Next (with an error sound).

- Mouse buttons: an action can run "When the button is held" (with "Hold for", 400 ms by default); that button's pressed actions then run on a short press only, and the held action's pill says "· held".
- Action settings: every choice (Runs, Act on, Search engine...) is a pull-down list; numbers keep their arrows.
- Windows' own volume pop-up is now hidden without a flash.
- Plug-in editors with many parameters build only the rows on screen.
- Other PCs: this PC is found and accepts connections only on networks set to Private in Windows and over Tailscale; on a Public network the page says so in one line with a link to Windows' network settings.

- Plug-ins: while OmniControl runs as administrator, a plug-in also loads only when every file in its folder (and its whole VST3 bundle) can be changed only by administrators and none of them is a link.
- Displays: the page's cards are made only when the page is first opened, so OmniControl uses less memory until then.

- Menus with many rows (the gadget's Font list) build only the rows in view, so opening them is lighter.

- Icons: a PNG added to Your icons is checked for its size before it is read, a very large one is refused in one sentence, and the rest is read straight at icon size; a removed or reloaded picture's memory is given back.
- Other PCs: messages to a paired PC wait in a bounded queue (only the newest value of a state or of the shared list is sent); a PC that stops taking them is disconnected and reconnects, and a request's wait now includes sending it.
- Settings changed quickly (a slider, a plug-in's window) are turned into file text once per pause instead of at every change.

- Effects: an open FX window remembers its last measured chain as a short digest instead of a copy of every plug-in's settings.

- Effects: while a plug-in's window is open, its settings are read only after it says they changed (VST2 plug-ins that say so) and are encoded and saved only when they really changed.

- Effects: a VST2 plug-in that changes without saying so (a preset loaded in its own window) is still followed live, checked every 2 seconds while its window is open.

- Logs: a flood of log lines can no longer take unbounded memory (the oldest routine lines are dropped and counted, errors kept); a line repeated back to back is written once with a count; logs roll over by their real size on disk.

- Restore: finishing or rolling back an interrupted restore checks the whole set from disk without holding every file in memory, then puts the files back one at a time.

- Other PCs: an imported area is written under a journal, so a crash or power cut in the middle of it is finished or undone at the next start instead of leaving the area half imported.

- Effects: watching Equalizer APO's config folder reads config.txt a line at a time and compares the chain file by size first, instead of loading whole files at every look.

- Effects: the FX window's chart measures one chain at a time; quick edits no longer load several copies of the same plug-ins or impulse responses at once, and a stopped measurement stops before its next plug-in or file is loaded.
- Effects: an impulse response file is read only up to the 10 seconds and two channels the IR Loader keeps, instead of whole.
- Effects: changing an IR Loader's Gain, Mix or another effect no longer reads and prepares its impulse response file again; a changed file is read once, and only the latest of quick file changes is prepared.
- Restore all on App settings no longer loads every page with a Restore defaults to see whether it can run, and a page's restore action no longer loads that page in the background; Undo reads the copy taken before the restore from disk.
- Changed: App settings > Start and close, "Free memory after closing" now defaults to 30 seconds, and has a new "Always" choice that frees the closed window's memory right away.

- Taskbar gadget > What it shows: the Upload and Download rows have a network adapter chip under their name (Auto = the choice on the Readings tab, or any one adapter), one for each, like the graphics card chip of the GPU rows.
- Hiding Windows' own volume pop-up now happens before it can be seen.
- Effects: a removed plug-in is unloaded only once the sound has moved on to the new chain, so removing one while sound plays is safer.
- Memory is no longer given back at start-up or after a short hide while OmniControl plays or records sound, as already after a long hide.
- Taskbar gadget: a double-click registers even if the mouse moves a little between the clicks.
- Fixed: links such as "Open on GitHub" did nothing when OmniControl ran as administrator (the Portable copy); they now open through Explorer in your normal session, and a failure is logged.

## 0.3.0 (22 Nov 2026)

- Added: Network traffic control's Upload limit and Download limit menus end with Block, which blocks only that direction for the program: Upload block is an outbound Windows Firewall rule (the program then cannot start new downloads either); Download block drops everything that arrives for the program through Windows Packet Filter (needs the driver and the Packet filter switch on). The row's On switch still blocks everything. The network service's protocol is now version 2 (install the service again after updating if it says it is from another version).
- Changed: the FX window's response charts show the whole chain as measured (a short test sweep played once through every switched-on effect, IR Loader and plug-ins included) a moment after each change, with Peak and Latency from the measurement and tags for a level-dependent effect, a reverb tail and Equalizer APO settings left out; the EQ and gain curve stays as a faint reference in the larger chart.
- Fixed: a removed effect could stay audible in Equalizer APO; its config is now written once per change, without the removed effect.
- Fixed: a removed plug-in is unloaded a moment after it leaves every running chain, instead of staying loaded until all effects stop.
- Changed: while a plug-in's window is open, its settings reach Equalizer APO and the FX window's chart live (within about a third of a second), not only when the window closes.


- Fixed: a program's download limit now holds from each new connection's first packet; before, every new connection ran unlimited for up to a second, so a browser opening many connections went well over its limit.
- Changed: a program's limit chips say "No limit" when no limit is on, and the Network traffic control status line says when a VPN tunnel (WireGuard, Tailscale) is up, since download limits don't reach traffic through it.
- Fixed: a backup that would be too large for OmniControl to read back is refused with one sentence and the previous backup is kept (also the automatic one before an import).
- Fixed: Undo after importing from another PC no longer forgets an area whose files could not be written back; it says so and a second Undo tries again.
- Fixed: a restore that failed part way and could not be rolled back (a file in use) no longer throws away its record; the next start finishes or rolls it back.
- Safer: importing Volume presets from another PC leaves out each effect's plug-in file and saved plug-in state, as the mixer and effect presets already did; a plug-in effect then shows as needing to be chosen again.
- Safer: when a paired PC imports your settings, your smart devices are handed over without account emails and without the text typed by recorded steps, the same as when devices are shared one by one.
- Safer: Setup removes an older per-user copy only when it was started without administrator rights for your own account; otherwise it leaves that copy in place and the finished page says to remove it from Apps & features.
- Safer: a device template's saved email and password are handed only to the kasa program; a template that runs any other program (for example one you imported) runs without them.
- Lighter: a device's own picture and your own PNG icons are decoded at the size they are drawn (twice that for sharpness on high-DPI screens) instead of full size, and the gadget's Font menu lets go of its font rows when it closes (looks unchanged).
- New: App settings, Start and close, "Keep recent pages ready" (off by default, which frees a page's view the moment you leave it): switched on, the open page and the last two visited stay built so going back is instant, and any other page goes once you have left it as long as "Free memory after closing" says (Never: kept); it uses more memory.
- New: App settings, Start and close, "Free memory after closing" (30 seconds, 1 minute, 2 minutes, 5 minutes, Never): how long the closed window stays ready to reopen instantly before its memory is freed; it was 5 minutes and is now 1 minute by default, and the next hide uses a new choice.
- Fixed: the taskbar gadget could show coloured blocks after a change of position, text colour or anything else that resized it; it now redraws whenever Windows gives it a new size.
- Faster first search: "Search settings..." makes only the pages that have a match (each page's words are read without making it), at the typing pause, instead of every page at the first letter; results and their order are unchanged.
- Faster and lighter: sliders, scroll bars, text boxes, switches, check boxes, drop-downs, the page lists' rows, ticked menu rows, the pane splitter and the menu pop-downs take their looks from control themes, so far fewer global styles are tried on every control (looks unchanged).
- Faster: the Displays page (and the Mouse page's inner groups) builds eight cards first and the rest right after, so its first frame shows sooner; looks and keys are the same.
- Faster: menu rows build their tag lists only when the row has tags (long menus such as the action picker's and the gadget's menus open sooner).
- Faster: the Volume page's level meters repaint only when a level moves by about a pixel and read less often while every meter is silent (the compressor and limiter cards too).
- Faster: the taskbar gadget no longer redraws, repaints or re-places itself on a reading that changed nothing it shows, and keeps its bitmap and picture buffer while its size is unchanged (less CPU at fast reading intervals).
- README: new screenshots of the Resources Readings tab and the Network traffic control page, drawn with made-up data (the screenshot tool can now draw both pages).
- Faster: typing in "Search settings..." no longer switches the page behind the results on every letter, only at the typing pause.
- Faster start: the Volume, Mouse and Trackpad, OSD and App settings pages are no longer made at start-up (about 140 ms); they are made when opened, App settings' "Restore all" making the others when App settings is first opened.
- New: App settings > Appearance "Use GPU drawing" (off by default): windows are drawn by the graphics card from the next start, for smoother scrolling and animations at about 40–80 MB more memory.

App settings > Features shows a feature that is not installed as "Not installed: run Setup to add it", its switch unavailable.

- Fixed: App settings > Backup and restore: importing a backup or wiping is now all or nothing. Everything is checked and a copy of each changed file kept before any setting changes; if OmniControl or the PC stops part way, the next start finishes the restore (or puts everything back when the kept files are damaged), so settings are never left half restored.
- Changed: releases are built by a GitHub Actions workflow from a verified version tag and carry build provenance attestations beside the SHA-256 sums; `tools\release.ps1` now only creates and pushes the tag.
- timing-log.txt's memory lines also give the figure Task Manager shows (the private working set).
- Lighter memory: the drawing library's image cache is kept small, and its caches are emptied when the windows are let go after a long hide.
- Lighter memory: OmniControl uses Windows' newer segment heap for its native memory, which gives freed memory back to Windows sooner.
- Changed: before the main window is let go after a long hide it closes its tooltips and pop-ups and gives up the keyboard focus, which may have kept it in memory (timing-log.txt still says whether it was collected).
- Lighter start: when OmniControl starts in the tray (with Windows, or "Start minimised"), the main window is built only when it is first opened (that first opening takes a moment longer, as after a long hide).
- Lighter idle: on a PC without a laptop screen the OSD no longer listens to Windows' brightness event; one read a moment after start decides.
- Faster sensors: the hardware sensor library ships precompiled, so the first temperature reading needs less start-up work (the download is about 0.5 MB larger).
- Lighter memory: at most 6 MB is allocated between two of the runtime's quick collections (PCs with a large processor cache used to allow tens of MB).
- Fixed: since 0.2.8 the small outlined buttons (Restore defaults, Add, Remove…), field-like pickers and confirm buttons, state buttons, and the cards of the Method menu and the gadget's Ready-made layouts showed Windows' plain button fill instead of their own fill and edge; they look as designed again.
- Lighter memory: every button, and tags, panes, group cards, tick boxes, set-up stages and status lines, carry their looks in themes of their own, so a button checks about 40 styles instead of about 160; nothing else looks different.
- Taskbar gadget: a double-click is now recognised by Windows' own rule (its double-click time and rectangle) even while the gadget redraws between the clicks; a small move between the presses no longer loses the click. New "Double-click time" card in Clicks (default: Windows' own).
